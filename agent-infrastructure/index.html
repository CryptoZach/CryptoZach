Agent infrastructure

Most agent guardrails do nothing, and you cannot know which ones without measuring.

This page documents the operating layer underneath an AI agent fleet that has been running since March 2026. Not a proposal and not a survey: a system in daily use, with the measurements that justified each part of it and the measurements that killed parts of it.

Every mechanism below exists because something went wrong first. Where a number appears, it was measured rather than estimated, and the date it was measured is stated.

The system

A fleet of AI coding agents works a single shared repository. They do research, drafting, verification, and infrastructure work on the same corpus, concurrently, over horizons far longer than any one context window holds.

Measuring whether a control works

The apparatus above accumulated faster than the evidence for it. So the first real instrument was one whose only job is to say whether any given control changes agent behavior at all.

The metric is saturation. For each control, measure the repeat-firing rate in the same workspace after an agent has already seen the signal. If an agent receives the same warning a dozen times in one workspace, the warning is not teaching anything. It is wallpaper, and its real effect is to raise the noise floor so the useful signals get ignored alongside it.

Several other classes return no verdict at all because they are under-sampled, and the instrument reports that rather than a flattering number: a precision estimate computed on nine events is not a precision estimate.

This is the discipline the rest of the page rests on. Build the instrument that could prove your system useless, then believe it.

Enforcement rungs

The saturation measurement forced a distinction that now governs every new rule.

A teaching rung depends on the agent recalling the rule while acting: prose in a session-start file, a memory entry, an advisory warning. An enforcing rung does not: a gate that refuses the commit, a hook that denies the call, or best of all an actuator that hands back the correct form so the wrong one is never expressible.

The rule that follows: a control shipped to a teaching rung is unenforced, and the honest thing is to say so rather than count it as delivered. Two corollaries, both learned the expensive way:

  • Promote on evidence of harm, never on elapsed time. A rule that has sat quietly for a month has not earned promotion; it has only failed to be noticed.
  • Measure the new control's precision before shipping it. Otherwise you rebuild the same cry-wolf problem one rung up, with more authority behind it.

The strongest form is the one that removes the choice. A checkout that refuses commits and whose refusal message names the correct command is categorically different from a warning that explains the same thing, because the first cannot be forgotten under time pressure.

Confabulation before capacity

Memory systems for agents are usually discussed as a capacity problem. In practice the failure that nearly broke this one was not forgetting.

It was an agent writing a confident reference to a finding that had never been established, which the next session then read as established, and built on. The corpus does not degrade gracefully under that. A single invented identifier becomes load-bearing within a few sessions.

The fix was not a better retriever. It was a referential-integrity constraint enforced at commit time: no agent may invent an identifier for a finding, a decision, or an open question, and if the identifier is not already in the corpus the slot must be left empty and flagged for a human. Semantic memory needs referential integrity more than it needs recall.

A second, quieter failure in the same family: procedural memory decays invisibly. Session-start procedure files sit under a hard size budget, and past that threshold the tail is silently truncated. A procedure that stops being read reports normal. The loading path is therefore part of the memory design, not plumbing.

Coordination is not a pointer to a live process

Agents first coordinated by passing messages. That lost work every single time an owner exited: the message arrived for a process that was gone, and the task sat marked as owned forever, invisible to every other agent.

Coordination moved to committed state, and a claim on a work item became a lease re-checked on every read. A dead claimer's item reverts to unowned rather than appearing owned. The general rule, which has since applied well outside this system: coordination state must be durable and re-derivable, never a pointer to something that can exit.

One corollary is worth stating separately because it is easy to get backwards. An absent process proves the process is gone. It never proves the work item has no owner. "Nobody is holding this right now" and "nobody is responsible for this" are different questions and need separate answers.

Isolation followed the same path. A shared working tree let concurrent agents corrupt each other's staged work in ways that only reproduced under specific interleavings, which made them maddening to diagnose. Every session now gets its own isolated tree and index.

Checks that pass for the wrong reason

A worked example, included because the failure is more instructive than the success.

A verifier was checking whether a set of external records was still live. It reported one as live. It was live, but the check had not established that: the network fetch had timed out, the output file was never cleared between calls, and the assertion had matched against the previous request's leftover bytes. Right answer, no measurement.

The correction was to clear state per call, treat a non-zero exit as no verdict rather than as a negative, and then re-run the whole thing against a deliberately fabricated identifier to confirm the check could still tell the difference. That last step is the one usually skipped.

A check never observed to fail has not been shown to work. A passing test tells you the assertion held, not that it held for the reason you believe. The companion rule, from repeatedly being wrong in the other direction: when something fails on model output, the verifier is the suspect before the model is.

The sharper version, which took longest to learn: when one observable has two possible causes with opposite remedies, testing the property they share will confidently prescribe the wrong fix for whichever half you cannot see. A burst rate-limit and an exhausted budget look identical at the call site and want opposite responses. So does a harness bug and a model regression. An instrument has to name the mechanism, not the symptom.

Context as a deliberately managed resource

Context is the budget everything else spends. Four rules govern it here.

  • Progressive disclosure. Of 72 skills, none load at session start. Each carries a description whose only job is to answer "does this apply to what I am about to do," and the body loads on invocation.
  • Offload by size. Any result above a fixed threshold goes to disk with a digest returned in its place, and a cost estimator is consulted before a large read rather than after.
  • Instrument the trajectory. Occupancy and headroom are queryable mid-task against an explicit rubric for when to checkpoint.
  • Compact by rotation, not by truncation. The durable memory index runs against a hard budget where roughly 81 percent of the space is pointer scaffolding rather than content. The tempting lever is shortening each entry's retrieval hook. That is the wrong lever: a hook that no longer says when the entry applies is dead weight still paying its full pointer cost. Rotating whole entries out to a searchable archive took the index from 130 entries at 16,677 bytes to 85 fully-hooked entries at 15,566 bytes, with 45 rotated and restorable.

What this is not

Stated plainly, because a page like this invites assumptions it should not get.

  • Not a product, and not available to use. It is internal infrastructure for one operator's research program.
  • Not a distributed system with users. The concurrency and consistency problems are real, but there is no external traffic, no service-level objective, and no on-call rotation.
  • Not machine-learning work. No model is trained, fine-tuned, or served here. The models are consumed through provider APIs, plus local inference for work that should not leave the machine.
  • Not container or VM isolation. Isolation is at the process and filesystem level. It solved a real corruption problem and it is not a security sandbox.
  • Not a benchmark. The measurements describe this system's own controls. They are not claims about agent behavior in general, and the observation spans are stated so they can be discounted accordingly.

The architecture underneath is the subject of sixteen USPTO applications across eight families. The surrounding research program is eight papers on SSRN, one accepted at Frontiers in Blockchain, and fifteen federal regulatory comment letters.
